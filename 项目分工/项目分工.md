## 当前进度判断

项目目前处在 **M1 核心框架前半段**：

- 已有 Unity 项目工程结构。
- 已导入 `Flooded_Grounds` 场景废墟资源包，可用于建筑、道路、障碍、氛围搭建。
- 已导入 `Julhiecio TPS Controller` 第三人称控制器资源包，已有角色、武器、AI、UI、音效、血量、弹药、丧尸 AI 示例等素材和脚本。
- `Assets/Scenes/SampleScene.unity` 目前基本仍是默认空场景，只检测到 Main Camera。

结论：下一步不建议从零写完整系统，而应先把现有资源包接入 `SampleScene`，做出“能移动、能射击、能刷丧尸、能判定胜负”的最小可玩 Demo。

## 详细任务拆分

### 简梓恒：项目整合与流程

1. 建立正式主场景：以 `Assets/Scenes/SampleScene.unity` 为基础，整理层级命名为 `Environment`、`Player`、`Enemies`、`Managers`、`UI`。
2. 确认项目使用内置渲染管线，避免误切 URP。
3. 创建或接入 `GameManager`：
   - 游戏状态：菜单、进行中、胜利、失败。
   - 模式枚举：无限模式、正常模式、冒险模式。
   - 统计击杀数、生存时间、当前波次。
4. 制定最小验收目标：
   - 玩家能进入场景。
   - 至少 1 种丧尸能追踪并攻击。
   - 玩家死亡会失败。
   - 正常模式击杀目标数量后胜利。
5. 每天结束前检查 Git 状态，记录哪些文件是当天新增或修改。

### 钱嘉琪：场景与关卡

1. 使用 `Assets/Flooded_Grounds/Prefabs` 搭建一条可玩的废墟街区路线。
2. 先完成小地图闭环：
   - 出生点。
   - 主战斗区。
   - 障碍和掩体。
   - 冒险模式撤离点。
   - 3-5 个丧尸刷新点。
3. 调整光照、天空盒、雾效和后处理，让场景符合末日夜晚氛围。
4. 修正 `Assets/World/DayNightCycle.cs`：
   - 类名改为 `DayNightCycle`。
   - 后续再实现昼夜旋转或固定夜晚参数。
5. 保证场景路线可走，不要让装饰物堵住玩家或丧尸路径。

### 王天阔：玩家与战斗

1. 从 `Julhiecio TPS Controller` 接入可用的第三人称角色预制体。
2. 完成基础操作验证：
   - WASD 移动。
   - 鼠标视角。
   - 跳跃。
   - 鼠标左键射击。
3. 接入至少两种武器：
   - 手枪或霰弹枪作为远程武器。
   - 棒球棍或武士刀作为近战武器。
4. 实现或配置玩家血量、受击、死亡。
5. 实现弹药规则：
   - 无限模式：无限弹药。
   - 正常模式：有限弹药，可拾取补给。
6. 输出一份“玩家操作与武器配置说明”，方便其他成员联调。

### 李勇明：丧尸、波次、UI 与音效

1. 从 `Julhiecio TPS Controller/Prefabs/AI/Zombi AI Sample.prefab` 接入第一版丧尸。
2. 配置三类丧尸参数：
   - 普通丧尸：慢速、低血量。
   - 快速丧尸：高速、低血量。
   - 胖丧尸：慢速、高血量、后续加入范围伤害。
3. 建立刷怪点和基础波次：
   - 无限模式：循环刷新。
   - 正常模式：击杀目标数量，例如 50 只。
   - 冒险模式：沿路线布置阻挡型丧尸。
4. 接入 HUD：
   - 血量。
   - 弹药。
   - 击杀数。
   - 生存时间或波次。
5. 接入基础音效：
   - 枪声。
   - 丧尸叫声。
   - 玩家受击声。
   - 胜利/失败提示音。

## 当前最重要的交付物

优先级从高到低：

1. `SampleScene` 中能控制玩家移动射击。
2. 至少一个丧尸能追踪并攻击玩家。
3. 玩家和丧尸都有血量和死亡逻辑。
4. 有刷怪点和击杀计数。
5. 有胜利/失败条件。
6. 再接 UI、音效、机关、三模式差异。

## 风险提醒

- 当前资源包很多，容易迷路；先用现成 Demo 预制体，不要急着重写全部系统。
- `DayNightCycle.cs` 当前类名和文件名不一致，Unity 会报脚本挂载问题，需要尽早修正。
- `SampleScene` 目前还没有接入玩家、丧尸和 UI，应把它作为第一优先级。
- 不要批量删除资源包文件。若资源过多，只整理引用和场景对象，删除文件需逐个明确路径处理。
